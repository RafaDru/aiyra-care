## Hipóteses (ordenadas)

1. **Erro React real na árvore de onboarding** — `OnboardingPage` monta fora de `AppLayout` ([`App.tsx`](../../../packages/web/src/App.tsx) L42), mas ainda sob `AppErrorBoundary` global ([`main.tsx`](../../../packages/web/src/main.tsx) L19). Qualquer throw em render (i18n, Ant Design `Steps`/`Form`, `MaskedDatePicker`, `MinorGuardianConsentFormItem`) gera exatamente este fingerprint. O campo `properties.component` no PG (primeira linha do `componentStack`) é necessário para distinguir.
2. **Corrida pós-`completeProfile`** — após `POST /auth/complete-profile`, `goToDependentsStep()` + `refreshSync()` atualizam `needsProfile` enquanto o wizard usa `sessionStorage` (`aiyracare.onboarding_wizard_step`). Documentado em [`auth-entry-onboarding.md`](../../features/auth-entry-onboarding.md). Improvável estourar boundary (erros de API vão para `setError`), mas redirect `Navigate` para `/` com estado inconsistente pode expor bug em filho compartilhado.
3. **Ruído / reabertura do bridge** — `CLIENT_ERROR_INCIDENT_BRIDGE` com feature `ui` na allowlist ([`CLIENT_ERROR_INCIDENT_BRIDGE.md`](../CLIENT_ERROR_INCIDENT_BRIDGE.md)) abre INC em `integration` com `MIN_COUNT=1`. Pode ser reincidência do defeito corrigido em dashboard (`ActiveCareCircleProvider` sempre montado em `AppLayout`) **ou** incidente distinto na mesma classe de telemetria.
4. **Falso agrupamento cross-rota** — usuário em `/onboarding` no momento do `componentDidCatch` (`window.location.pathname`), mas a pilha pode apontar para provider compartilhado (`AuthProvider`, `LlmActivityProvider`) se a falha for timing de auth/compliance.
