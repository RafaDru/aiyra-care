# Investigação — AppErrorBoundary na rota `/` (Dashboard/shell)

- **Incidente ligado:** `96a2e898-9d36-4495-82e6-76eb17fc555e`

- **Fingerprint telemetria:** `036967be53b57d23` → `ui|ui_boundary|error` (`reportUiBoundaryError`, `error.name === 'Error'`)
- **Ambiente:** integration (web)
- **Tier correção:** 0

## Sintoma

Exceção React capturada pelo `AppErrorBoundary` global (`main.tsx`) na rota `/` (Dashboard dentro de `AppLayout`). Não é falha HTTP tratada em `load()` — é crash de render.

## Causa raiz

Após #49 (`ActiveCareCircleProvider` + `useActiveCareCircle` no `Dashboard`), o provider só envolvia o shell quando `configured && user` em `AppLayout.tsx`. O `Dashboard` (e rotas `/family`) **sempre** chamam `useActiveCareCircle()`, que faz `throw new Error('useActiveCareCircle must be used within ActiveCareCircleProvider')` sem o provider — `error.name` genérico `Error`, fingerprint acima.

Cenários afetados: modo legado sem Supabase (`!configured`, `RequireAuth` libera `<Outlet />`) e qualquer render do shell sem par `configured && user` alinhado ao outlet autenticado.

## Correção

- `AppLayout`: envolver **sempre** o layout com `ActiveCareCircleProvider` (o provider já no-op quando `!configured || !user`).

## Verificação

- Revisão estática: `Dashboard` + `AppLayout` + `ActiveCareCircleContext`.
- Regressão API existente: `platform-defect-fix-dispatch.test.ts` (sem mudança de contrato).
